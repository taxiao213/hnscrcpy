# hnscrcpy v1.0.3

鸿蒙 NEXT（HarmonyOS NEXT）投屏远控桌面工具，类似 scrcpy 的体验：**打开即用，零外部环境依赖**——JRE、hdc、投屏组件全部内置，无需安装 Java 或任何开发环境。

## ⚡ 新增

- **ASCII 打字快通道**：在投屏窗口直接打英文/数字/符号时，单字符延迟从 ~900ms 降至 **~130ms**（接近实时的打字手感）。全部 95 个可打印 ASCII 字符（含大写与 !@#$ 等移位符号）逐键直发 uinput 键盘事件，不再经设备侧「uiInput inputText」重通道（每次要起设备侧进程）；中文输入仍走原有批量注入通道。与文本攒批共用同一控制线程，保证「先文后键」顺序不错乱。键码表已在真机逐键标定
- **「窗口置顶」状态可见**：菜单「窗口置顶」（⌘T）置顶后此前无任何标记，现在置顶时显示 ✓ 勾选

## 🔧 修复

- **投屏画面周期性卡顿/黑屏闪烁（看门狗误杀）**：hosScrcpy 1.0.20 起静态画面不再强制推帧，旧看门狗把「手机画面静止」误判为断流，每 ~25 秒杀流重连一次，表现为画面周期性冻结-黑屏-闪帧。看门狗改为**先探活再判死**：静默时经桥内通道执行只读命令验证守护进程存活，探活正常 = 静态画面，绝不重连；另加「输入预言机」（有点击/键盘注入却画面不变才快速判死）与 5 分钟纯静默兜底
- **应用闪退/崩溃（use-after-free）**：重连/关窗/截图与解码器环形缓冲释放存在竞态——渲染线程可能读取已释放的 14.5MB 原生内存（mmap 大对象，释放后即 unmap），导致 JVM 段错误无声退出。环形缓冲改为**永不显式释放**（交 GC 统一管理），重连时同时清空旧帧槽位，彻底消除这一类崩溃
- **打开投屏长时间黑屏/主窗口卡死**：会话建立（hdc 初始化 + 设备侧投屏服务握手，约 5-7s）此前跑在界面线程上，双击设备后整个应用冻结。改为**窗口秒开**、会话后台异步建立，状态栏实时显示进度；流就绪后客户端**主动催 IDR 关键帧**，首帧不再等设备「心情好」
- **软键盘输入延迟大**：打字攒批等待 150ms→80ms；按键与文本注入从「每次本地起 hdc 子进程」改为**桥内通道**（既有连接直发，单次省 ~140ms+）；Enter/退格前的文本冲刷等待上限 5s→2.5s，不再偶发卡死感
- **「关于」页版本号与发布版本不符**：版本号此前在代码中硬编码（v1.0.2 显示 1.0.1），改为构建期从 pom.xml 自动注入，永远与发布 tag 一致

> 快通道键码表已用 `scripts/spike-keymap.sh` 在真机逐键标定（修正了文档值的两个错误：空格=2050 而非 2052、方向键=2012-2015 而非 2071-2074）。如遇异常可用 `-Dhnscrcpy.keyFastPath=false` 整体回退到原通道。

## 🛠 稳定性

- 新增全局未捕获异常落盘 + JVM 崩溃尸检文件（macOS/Linux: `/tmp/hnscrcpy_hs_err_pid*.log`，Windows: `%TEMP%`），以后任何闪退都有现场可查
- 重连竞态收口：关窗与重连/启动互斥，调度器关闭后的迟来回调安全丢弃
- 单测 86 → 137：新增看门狗判死矩阵、重连清帧回归、解码器关闭安全性、shell 通道回退、版本号注入、置顶勾选态、ASCII 快通道键码表等用例

## 📖 使用

1. 手机开启「开发者模式 → USB 调试」（或无线调试），连接电脑
2. 打开 hnscrcpy，双击设备开始投屏
3. 快捷键：⌘/Ctrl+S 截图 · ⌘/Ctrl+R 旋转 · ⌘/Ctrl+V 粘贴到手机 · ⌘/Ctrl+I 中文输入
